## 2. Создание схемы и всех шести таблиц

**Куда:** Query Tool новой базы. **Когда:** один раз, до импорта данных.

Таблицы: `customers` (заказчики), `products` (изделия), `resources` (материалы и операции), `recipe_items` (состав изделия), `orders` (шапка заказа), `order_items` (позиции заказа).

```sql
CREATE SCHEMA IF NOT EXISTS day9;
SET search_path TO day9, public;
CREATE TABLE IF NOT EXISTS customers (id varchar(9) PRIMARY KEY,name text NOT NULL,inn varchar(12),address text NOT NULL,phone text NOT NULL);
CREATE TABLE IF NOT EXISTS products (id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,code text NOT NULL UNIQUE,name text NOT NULL,unit text NOT NULL CHECK(unit IN ('шт','м','ч')));
CREATE TABLE IF NOT EXISTS resources (id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,code text NOT NULL UNIQUE,name text NOT NULL,kind text NOT NULL CHECK(kind IN ('material','operation')),unit text NOT NULL CHECK(unit IN ('шт','м','ч')),unit_price numeric(14,2) NOT NULL CHECK(unit_price>=0));
CREATE TABLE IF NOT EXISTS recipe_items (product_id integer NOT NULL REFERENCES products(id),resource_id integer NOT NULL REFERENCES resources(id),norm numeric(14,4) NOT NULL CHECK(norm>0),PRIMARY KEY(product_id,resource_id));
CREATE TABLE IF NOT EXISTS orders (id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,number text NOT NULL UNIQUE,order_date date NOT NULL,customer_id varchar(9) NOT NULL REFERENCES customers(id));
CREATE TABLE IF NOT EXISTS order_items (id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,order_id integer NOT NULL REFERENCES orders(id),line_no integer NOT NULL CHECK(line_no>0),product_id integer NOT NULL REFERENCES products(id),quantity numeric(14,3) NOT NULL CHECK(quantity>0),unit_sale_price numeric(14,2) NOT NULL CHECK(unit_sale_price>=0),discount_amount numeric(14,2) NOT NULL DEFAULT 0,UNIQUE(order_id,line_no),CHECK(discount_amount>=0 AND discount_amount<=quantity*unit_sale_price));
```


**Что объяснить:** `PRIMARY KEY` однозначно определяет строку; `REFERENCES` создаёт внешний ключ; `UNIQUE` запрещает дубликаты кодов; `CHECK` проверяет значения; `NOT NULL` требует заполнения. `recipe_items` имеет составной ключ `(product_id, resource_id)`.

После выполнения обновите **Schemas → day9 → Tables**: должны появиться 6 таблиц.

## 3. Импорт шести исходных заказчиков из JSON

**Важно:** нужен **именно** `Заказчики.json` из «Приложения 2» задания «День 9». В нём должно быть **6 объектов**. Исходный ключ `addres` (с одной `s`) соответствует столбцу SQL `address`. Коды `000000001` и подобные храним как строки, иначе пропадут ведущие нули.

Сохраните JSON рядом с `import_customers.py`. Ниже весь Python-код (также есть отдельным файлом в комплекте):

```python
"""Импорт шести исходных заказчиков. Запускать после создания таблиц."""
import json
from pathlib import Path
from getpass import getpass
import psycopg

path = Path(__file__).with_name('Заказчики.json')
if not path.exists():
    raise SystemExit('Нет файла Заказчики.json. Возьмите оригинал из Приложения 2.')
records = json.loads(path.read_text(encoding='utf-8-sig'))
if not isinstance(records, list) or len(records) != 6:
    raise SystemExit('Ожидается массив из 6 исходных заказчиков.')
rows = [(str(r['id']), r['name'], r.get('inn') or None, r['addres'], r['phone']) for r in records]
host = input('Host [localhost]: ').strip() or 'localhost'
port = input('Port [5432]: ').strip() or '5432'
db = input('Database [day9_db]: ').strip() or 'day9_db'
user = input('User [postgres]: ').strip() or 'postgres'
password = getpass('Password (можно пустой): ')
kwargs = dict(host=host, port=port, dbname=db, user=user, connect_timeout=5)
if password: kwargs['password'] = password
with psycopg.connect(**kwargs) as conn:
    with conn.cursor() as cur:
        cur.executemany("""INSERT INTO day9.customers (id,name,inn,address,phone)
        VALUES (%s,%s,%s,%s,%s)
        ON CONFLICT (id) DO UPDATE SET name=EXCLUDED.name, inn=EXCLUDED.inn,
        address=EXCLUDED.address, phone=EXCLUDED.phone""", rows)
print('Успешно импортировано:', len(rows))
```


### Запуск на Windows (PowerShell)

```powershell

.\.venv\Scripts\python.exe -m pip install "psycopg[binary]"
.\.venv\Scripts\python.exe import_customers.py
```

### Запуск на Linux

```bash
python3 -m venv .venv
./.venv/bin/python -m pip install 'psycopg[binary]'
./.venv/bin/python import_customers.py
```

Введите хост (обычно `localhost`), порт (`5432`), имя созданной базы, пользователя и пароль. **Ожидается:** `Успешно импортировано: 6`.

**Если Python/psycopg установить нельзя:** покажите преподавателю скрипт и попросите доступ к среде Python; не придумывайте шесть строк. Остальные таблицы и расчёты можно показать без импорта JSON.

Проверка в Query Tool:


## 6. SQL-запросы для демонстрации

Каждый `SELECT` можно запускать повторно: он не меняет данные. Выполняйте **по одному запросу** в Query Tool, выделяя нужный блок.

### 6.1. Состав изделия и цена каждой операции/материала

Должно быть 12 строк; основная ткань: 1,5 × 820 = 1 230 ₽ на пару.

```sql
SELECT r.name, r.kind, ri.norm, r.unit, r.unit_price,
       ROUND(ri.norm * r.unit_price, 2) AS cost_per_product
FROM day9.recipe_items ri
JOIN day9.resources r ON r.id = ri.resource_id
JOIN day9.products p ON p.id = ri.product_id
WHERE p.code = 'НФ-00000006'
ORDER BY r.id;
```

### 6.2. Разделение затрат: материалы и операции

Ожидается `material = 2162`, `operation = 1150`.

```sql
SELECT r.kind, ROUND(SUM(ri.norm * r.unit_price), 2) AS cost_per_product
FROM day9.recipe_items ri
JOIN day9.resources r ON r.id = ri.resource_id
GROUP BY r.kind ORDER BY r.kind;
```

### 6.3. Потребность всего заказа по каждому ресурсу

Для ткани должно быть 7,5 м и 6 150 ₽.

```sql
SELECT o.number, p.name AS product, r.name AS resource, r.unit,
       oi.quantity, ri.norm,
       oi.quantity * ri.norm AS required_quantity,
       r.unit_price,
       ROUND(oi.quantity * ri.norm * r.unit_price, 2) AS cost
FROM day9.orders o
JOIN day9.order_items oi ON oi.order_id = o.id
JOIN day9.products p ON p.id = oi.product_id
JOIN day9.recipe_items ri ON ri.product_id = p.id
JOIN day9.resources r ON r.id = ri.resource_id
WHERE o.number = '1'
ORDER BY r.id;
```

### 6.4. Проверка, что заказанные изделия имеют рецепт

Ожидается **0 строк**.

```sql
SELECT DISTINCT p.code, p.name
FROM day9.orders o
JOIN day9.order_items oi ON oi.order_id = o.id
JOIN day9.products p ON p.id = oi.product_id
WHERE o.number = '1'
  AND NOT EXISTS (SELECT 1 FROM day9.recipe_items ri WHERE ri.product_id = p.id);
```

### 6.5. Главный расчёт себестоимости заказа

Ожидается **16 560 ₽**.

```sql
WITH product_cost AS (
  SELECT ri.product_id, SUM(ri.norm * r.unit_price) AS unit_cost
  FROM day9.recipe_items ri
  JOIN day9.resources r ON r.id = ri.resource_id
  GROUP BY ri.product_id
)
SELECT o.number, ROUND(SUM(oi.quantity * pc.unit_cost), 2) AS production_cost
FROM day9.orders o
JOIN day9.order_items oi ON oi.order_id = o.id
JOIN product_cost pc ON pc.product_id = oi.product_id
WHERE o.number = '1'
GROUP BY o.id, o.number;
```

### 6.6. Сумма продажи с учётом скидки

Ожидается `before_discount = 16560`, `discount = 828`, `payable = 15732`.

```sql
SELECT o.number,
       ROUND(SUM(oi.quantity * oi.unit_sale_price), 2) AS before_discount,
       SUM(oi.discount_amount) AS discount,
       ROUND(SUM(oi.quantity * oi.unit_sale_price - oi.discount_amount), 2) AS payable
FROM day9.orders o
JOIN day9.order_items oi ON oi.order_id = o.id
WHERE o.number = '1'
GROUP BY o.id, o.number;
```

**Почему скидка считается отдельно:** если присоединить к позиции заказа 12 ресурсов и вычитать скидку в каждой строке, скидка ошибочно умножится на 12.

## 8. Что говорить преподавателю

**Короткий ответ (30–60 секунд):**

> Я создал в PostgreSQL схему day9 с шестью таблицами. Заказчики и изделия хранятся отдельно, чтобы не дублировать сведения. Таблицы связаны пятью внешними ключами. Цена ткани находится в resources, норма расхода — в recipe_items, количество брюк — в order_items. Запрос соединяет эти данные с помощью JOIN, умножает норму на цену и количество, а затем суммирует. Себестоимость пары — 3 312 рублей, пяти пар — 16 560 рублей. Скидка 828 рублей относится к продаже, поэтому к оплате 15 732 рублей.

**Короткие вопросы и ответы:**

- **PK?** Первичный ключ, уникальный идентификатор строки.
- **FK?** Внешний ключ, ссылка на существующую строку другой таблицы.
- **JOIN?** Соединяет строки по связанным ключам.
- **GROUP BY?** Группирует строки для расчёта `SUM` по каждой группе.
- **Почему 6 таблиц, а не одна?** Избегаем повторения телефона, названия изделия и других данных.
- **Почему количество 5 в order_items?** Это характеристика покупки, а не изделия.
- **Почему рецепт отдельно?** Одно изделие состоит из нескольких ресурсов, один ресурс может входить в разные изделия.
- **Где цена 820, норма 1,5, количество 5?** `resources.unit_price`, `recipe_items.norm`, `order_items.quantity`.
- **Зачем NUMERIC, а не FLOAT?** Для точных десятичных цен и норм.
- **Почему 7 заказчиков?** Шесть импортированы из JSON, седьмой Томилин добавлен для демонстрационного заказа.
- **Сколько стоит изготовить 2 пары?** 6 624 ₽.
- **Какие ресурсы имеют норму 2 шт?** Пуговицы на карманах и на поясе.
- **Что такое SELECT?** Запрос чтения, который показывает результат, но не создаёт новую таблицу.

**Что показать на экране:** дерево `day9 → Tables`, содержимое `customers`, `resources`, `recipe_items`, `order_items`, ERD, запросы 6.3, 6.5 и 6.6. Не выдавайте результат импорта за выполненный, если JSON не был загружен.

В архиве будет папка `day9-postgresql-main`. **Команды только скачивают файлы**, они не создают базу автоматически.

### Если в репозитории лежат отдельные SQL-файлы

На Linux после создания пустой базы можно выполнять:

```bash
psql -X -v ON_ERROR_STOP=1 -h localhost -U postgres -d day9_db -f 01_schema.sql

```

Если в репозитории **только README**, копируйте блоки из README в Query Tool. В `psql` команда `-f` работает только с реально существующими файлами.

### Резервный вариант — готовый дамп

Если `day9_backup.sql` загружен в репозиторий, можно восстановить его в **новую пустую базу**, но в исходном дампе есть команды `OWNER TO postgres`, поэтому при недостатке прав могут быть ошибки. Для демонстрации создания с нуля используйте SQL выше.

## 10. Типовые ошибки

| Сообщение | Причина / действие |
|---|---|
| `psql: command not found` | Нет клиента PostgreSQL или он не в PATH; работайте через pgAdmin либо обратитесь к преподавателю |
| `permission denied to create database` | Нет прав на создание БД; попросите учебную базу |
| `password authentication failed` | Неверный пользователь/пароль, проверьте данные подключения |
| `relation does not exist` | Неверная база/схема; используйте `day9.products` и т. п. |
| `schema day9 already exists` | Работа уже выполнялась; используйте новую пустую БД |
| `duplicate key value` | Данные вставлены повторно, проверьте таблицы |
| `current transaction is aborted` | Исправьте исходную ошибку, выполните `ROLLBACK` в том же сеансе |
| `foreign key violation` | Сначала создайте родительскую запись (заказчика/изделие/ресурс) |
| В `customers` только 1 | Нет импорта оригинального JSON с шестью заказчиками |
| Себестоимость не 16560 | Проверьте 12 норм и цен, а также количество 5 |
